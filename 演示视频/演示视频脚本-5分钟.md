# Table-Talker · 5 分钟演示视频脚本

> 目标观众：评委（11 位 PC + 决赛领导）
> 总时长：**5 分钟**（决赛要求覆盖功能 + 架构 + AI 算法及优化）
> 录制要求：**配音 + 字幕**（双保险，安静环境也能看懂）
> 工具推荐：OBS（屏录）+ 剪映（字幕 + AI 配音）
> 演示前置条件：双终端跑起来——后端 8000、前端 8080；确保 mock 模式（无需 VPN 也能演）

### 00:30 – 01:30 · 场景 1 销售归因（双模式核心展示）

**操作**：
1. 浏览器进入 Table-Talker 主界面
2. 左侧栏点击第一条「Q1 销售归因：为什么华南掉了 12%」
3. **强调"商业语言"模式 toggle 高亮**
4. 14 步 trace 流式动画跑完
5. 答案区 typewriter 逐字打出
6. 圆环图 + 柱图 + 异常洞察自动出现
7. **顶部 toggle 一键切到"专家"模式** → 同一答案换风格

**旁白**（边操作边讲）：
> 「我们打开 Table-Talker，左侧是历史对话，每一条都是真实业务问题。
> 比如这个：'Q1 华南销售为什么环比下滑 12%？'
>
> 系统进入 14 步推理流程——你能看到 GraphRAG 社区检索、TTL 业务术语推理、
> 多次 SQL 生成与自检——这是 Table-Talker 的差异化所在：
> **它不是简单的 NL2SQL，它会理解业务语言**。
>
> 商业语言模式给管理者：结论先行，含 So What 和建议。
> 一键切到专家模式——同一答案换风格：含计算口径、相关系数、突变点。
> 一个产品，两种人格。」

**字幕亮点**：
> 14 步可解释推理 ・ GraphRAG + TTL ・ 双模式 = 一个产品两种人格

---

### 01:30 – 02:15 · 场景 2 HR 月报（证明通用性）

**操作**：
1. 左侧栏切到「HR 月度复盘 · 2026/04」
2. trace + 答案 + 图重新跑一遍
3. 切到「财务 P&L · 部门偏差」(快速展示，不全程播)

**旁白**：
> 「同一个产品，同一个引擎。换数据集——员工分析。
> 它发现 BU-3 认证密度低于均线，38 人证书过期未续，**自动给出建议**。
>
> 再换——财务部门偏差。研发部超支 18.7%，Top1 拖累。
>
> **从销售到 HR 到财务——'任何业务表都能聊'**。这才是企业级数据分析。」

**字幕**：
> 销售 → HR → 财务：通用业务分析平台

---

### 02:15 – 03:00 · 场景 3 ARPU 异常（专家深度 + 引用溯源）

**操作**：
1. 切到「运营商 ARPU 异常排查」（默认专家模式）
2. trace 跑到第 9 步时**指出** "SQL 生成 · 尝试 2：校验失败：fin 表 month 字段为 string 需 cast"
3. 答案出来后，**点击"引用溯源"展开** → 看到 SQL + 数据集 + 字段 + 样例
4. 高亮强相关 r=0.81 这条洞察

**旁白**：
> 「这是更高复杂度的场景：运营商套餐迁移引发的 ARPU 异常。
>
> 注意第 9 步：**SQL 生成尝试 2，因为字段类型不匹配自动反思修正**。
> 这是 Table-Talker 的核心机制——4 次重试 + Critic 自检——显著提升复杂查询成功率。
>
> 每一条结论都能点开追溯——用了哪个数据集、哪几列、跑了什么 SQL。
> **结论不可信？看它怎么算的**。」

**字幕**：
> 多次 SQL 重试 · Critic 自检 · 100% 引用可溯源

### 03:00 – 03:30 · 三态输出（聊天 → 看板 → 报告）

**旁白**：

## 视频后期制作清单

### 必做
- [ ] **配音**：自己录 / 剪映 AI 配音（专业男声"声鸣"或女声"晓晓"）
- [ ] **字幕**：剪映自动识别字幕，校对错别字（特别是技术术语）
- [ ] **片头 logo**（3 秒）：Table-Talker logo + slogan
- [ ] **片尾**：团队信息 + 联系方式

### 加分项
- [ ] **关键节点黄色框**高亮（如点击"钉到看板"那一刻）
- [ ] **慢镜头**：14 步 trace 第 9 步"SQL 重试"打个慢镜头突出"自反思"
- [ ] **指标卡数字滚动**：批量评测处用 5x 速度让进度条/数字快速变化
- [ ] **配 BGM**：低音量科技感 BGM（剪映自带"AI 科技"系列）

### 不做
- ❌ 花哨转场（cube、glitch 等）：太乱
- ❌ 过度音效：弱化主线
- ❌ 字幕太花（彩色、抖动）：评委看不清

## 常见翻车点提前避免

| 风险 | 应对 |
|---|---|
| 网络抖动 → SSE 卡顿 | **录制时关闭后端真实模式，用 MOCK_MODE=true** |
| 浏览器缓存导致样式错位 | 录制前清缓存（Cmd+Shift+R） |
| 字体加载慢 | 提前打开页面 30 秒预热 |
| 鼠标点击没反应 | 屏录工具用 60fps，避免漏帧 |
| 视频太长 | 严格按时间轴录，超时立即剪 |
| 字幕错别字 | 剪映自动识别后**逐字过一遍**，特别是 GraphRAG / TTL / NL2SQL |
