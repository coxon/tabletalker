### 00:55 – 02:10 · 🌟 高潮 1：现场提问 → 三表 JOIN（75 秒）

> **这是视频里最关键的 75 秒，写脚本时反复推敲到字。**

**前置画面**（10 秒）：
- 桌面浮窗显示一张白纸 "假设评委现场说：'Q1 华南区销售为什么环比下滑 12%？哪些 BU 拖累最大？跟员工流动率有没有关系？'"
- 配音：
> 「假设你是评委，现场说一个不预设的复杂问题——
> 这是真正考验通用能力的时刻。」

**操作**（55 秒）：
1. 输入框打字：`Q1 华南销售为什么环比下滑 12%？哪些 BU 拖累最大？跟员工流动率有没有关系？`
2. 按回车 → 14 步 trace 流式动画启动
3. **关键节点放慢 / 高亮**：
   - Step 3：`GraphRAG 社区检索` badge 闪烁，配音"AI 检索到 3 个相关业务社区：销售归因、HR 流动、跨域关联"
   - Step 7：`TTL 推理与补全` badge 闪烁，配音"业务术语翻译：'华南'→region_l1, 'Q1'→2026Q1, '流动率'→sales × employee 跨表"
   - Step 8 → 11：4 次 SQL 重试可视化（第 9 步 retry 标记）
   - **🌟 Step 12 关键停顿 1.5 秒**：配音"它发现要 JOIN 3 张表——sales_orders × employee_analytics × fin_pnl_monthly"
4. 答案 typewriter 流出（5 秒）：
   ```
   华南区 Q1 同比下滑 12%，主因是 BU-3：
   ① 客户经理流失率 18%（员工分析数据）
   ② BU-3 销售贡献度 32%→22%（销售订单）
   ③ BU-3 预算执行偏差 +15%（财务数据）
   
   三个数据集交叉印证：人才流失 → 签单链路断 → 业绩下滑。
   ```
5. 滚动展示：折线图 + 柱状图 + **数据来源 SQL 展开**（评委能看到三表 JOIN）

**配音节奏**（不急不慢）：
> 「14 步推理流程，每步可见。
> 注意第 3 步 GraphRAG，AI 自动检索到 3 个相关业务社区——它**听懂了**这是个跨域问题。
> 第 7 步 TTL 推理，把'华南''Q1''流动率'翻译成具体数据库字段。
> 第 8 到 11 步：4 次 SQL 自我修正——这是工程鲁棒性。
> 然后**重点来了**——
> 它知道要 JOIN 三张表：销售、员工、财务。
>
> 30 秒后，得到的不是数据，是**一段含因果链的洞察**：
> 人才流失 → 签单链路断 → 业绩下滑。
> 这是 AI 真正在'分析'，不是'查询'。」

**字幕高亮**：

## 录制注意事项（v2 升级版）

### 关键动作放慢

```
00:55-02:10 这 75 秒是 WOW 段，节奏放慢：
  - 每个 trace step 停留 0.3-0.5 秒
  - Step 12 (执行 SQL) 关键停顿 1.5 秒（让评委理解"它在 JOIN 三表"）
  - 答案 typewriter 速度调到 30ms/字符（比默认慢一倍）
```

### 配音 vs 操作对齐

```
错：操作完了再配音 → 视觉听觉脱节
对：配音先行 0.5 秒 → 用户先听到关键词 → 再看到对应动作

例如：
  "它知道要 JOIN 三张表" ← 先说出来
  操作：trace 第 12 步高亮 ← 0.5 秒后视觉对应
```

### 字幕辅助

```
关键金句 + 数字必上字幕：
  - "1.7 天 → 30 秒"（首段）
  - "AI 自动跨 3 张表 JOIN"
  - "5 个国产模型 · 节省 60% Token"
  - "9.85x ROI · 首年回本"
```

### 镜头切换

```
不要：从头到尾一个屏幕 → 评委审美疲劳
要：5 段中插入 PPT 静帧（架构图、ROI 数字、路线图）
比例：屏幕录制 75% / 静帧 25%
```

### 配 BGM

```
推荐：剪映 AI 科技系列 02 / 04（节奏稳、有起伏）
音量：旁白 100%，BGM 30%（不抢声）
```
