# Table-Talker · 产品意图与需求梳理

> 版本：v0.1（产品意图阶段，先于 PRD）
> 时间：2026-05-03
> 范围：完整产品愿景 + 7 天比赛 MVP 边界

---

## 一、一句话定位

> **让企业每个人都有一位"私人数据分析师"——用日常对话，从结构化数据里挖洞察、出看板、写报告。**

口号备选（按场景挑）：
- **"会说话的数据"**（对决策者讲）
- **"Stop writing SQL, start asking questions"**（对技术人讲）
- **"从一句话到一份报告"**（对运营讲）

---

## 二、解决什么问题

### 2.1 真实痛点（按角色分）

| 角色 | 现状 | 损失 |
|---|---|---|
| 业务管理者（VP/总监） | 想看个数据 → 提需求 → 等 1-3 天 → 数据来了但跟想的不一样 → 再提需求 | 决策被动、错过窗口 |
| 业务运营（HR/财务/销售运营） | 自己在 Excel/PowerBI 折腾 2-3 小时，跨表关联做不出来 | 时间成本、精力消耗 |
| 数据分析师 | 80% 的时间在做"重复性、临时性"取数 | 没空做真正深度的分析 |
| IT/数据团队 | 维护一堆固化看板，临时需求也得手工写 | 永远在救火 |

### 2.2 我们的机会

1. 大模型已经能"读懂业务问题 + 写 SQL + 看图说话"
2. 国产模型成本进入可商用区间
3. 企业 AI 优先战略，预算就位
4. 同类产品（Tableau/PowerBI）老化、ChatGPT 不能用（合规）、自建 NL2SQL 工具门槛高

## 三、用户与场景

### 3.1 双模式（核心创新点）

> **同一个产品，两种"皮肤"。一键切换，背后是同一个 Agent。**

| 维度 | 🟢 商业语言模式（默认） | 🔵 专家模式 |
|---|---|---|
| 目标用户 | 部门 Leader / 总监 / VP | HR Ops / 财务分析 / 销售运营 / 数据分析师 |
| 核心诉求 | "给我结论 + 给我能讲给老板的那句话" | "让我看见过程 + 让我能调" |
| 默认信息密度 | 低（结论先行 + 1 张图 + 1 句话洞察） | 高（结论 + 数据集来源 + SQL + 多张图 + 详细推理） |
| Trace（推理过程） | 默认收起 | 默认展开 |
| 自动总结风格 | 商业语言、有 So What、含建议 | 客观陈述、不主观判断 |
| 默认追问建议 | 业务方向：「同比变化」「对比同行」「下季度预测」 | 技术方向：「换 group by」「看分布」「不含离群点」 |
| 输出粒度 | 结论 + 图表 + "导出汇报"按钮 | 数据表 + SQL + Notebook 导出 |
| 数据集选择 | AI 自动推断 | 手动选/混合 |

### 3.2 通用场景矩阵（不聚焦，但 Demo 必须覆盖多领域）

| 场景域 | 典型问题 | 对应公开数据集 | Demo 优先级 |
|---|---|---|---|
| 👥 人力资源 | "AI 技能员工持证率？哪些 BU 偏低？" | employee_analytics | P0 |
| 💰 销售零售 | "Q1 各区域同比？哪几个门店下滑？" | retail / sales | P0 |
| 📊 业务运营 | "工作日 vs 周末客流差多少？" | traffic | P1 |
| 🎬 行业洞察 | "2023 年票房 Top10？类型分布？" | movies | P1 |
| 🏘️ 宏观分析 | "老龄化最严重 5 个省份" | population | P2 |
| 🌦️ 资产/物流 | "近 5 年北京 7 月气温走势？" | weather / shipping | P2 |

> **Demo 策略**：评委追问时**轮播 3 个不同域场景**，证明"任何业务表都能聊"。

## 四、产品功能架构（三层）

```
┌─────────────────────────────────────────────────────────┐
│ 输入层（统一入口）：自然语言对话                            │
│   ├─ 直接问                                              │
│   ├─ 拖文件入对话框                                        │
│   ├─ @mention 数据集                                      │
│   └─ 模版选择（"帮我做月度复盘"）                           │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│ 推理层（AI Agent 核心）                                    │
│   ├─ 路由：选数据集（GraphRAG 社区检索）                    │
│   ├─ 语义补全：TTL 推理（业务术语→字段）                    │
│   ├─ Code Gen：NL → SQL/pandas（多次重试）                 │
│   ├─ 执行：受限沙盒                                        │
│   ├─ 自动选图：根据数据形态                                 │
│   ├─ 总结生成：双模式不同风格                               │
│   └─ 引用溯源：结论 → 数据行 + SQL                          │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│ 输出层（三态：聊天是入口，看板/报告是输出）                  │
│   ├─ 临时回答：单/多轮对话                                  │
│   ├─ 看板（"钉住"）：多图表 Dashboard，可分享                │
│   └─ 报告（"生成报告"）：多页 Word/PDF，自动拆子问题         │
└─────────────────────────────────────────────────────────┘
```

### 4.1 输出三态详解

| 形态 | 触发方式 | 内容 | 典型用途 |
|---|---|---|---|
| **临时回答** | 默认 | 1 段结论 + 1 张图 + 1 个表 + 追问建议 | 例会前查证、临时数 |
| **看板（Pin Board）** | "钉住此分析" / "保存为看板" | 多个图表 + 文字洞察组合，URL 可分享 | 月度复盘、订阅推送 |
| **报告（Report）** | "生成完整报告" | 大模型自动拆 5-15 个子问题 → 多页 Word/PDF | 月报、季报、汇报材料 |

> **关键**：三态不是三个独立产品，是**同一个对话流的三种"凝固"方式**。聊天 → 钉住几个图 → 形成看板；聊天 → 自动拆解 → 形成报告。

## 五、数据接入分层策略

| 优先级 | 类型 | 价值 | 比赛是否做 |
|---|---|---|---|
| **P0** | 文件上传（CSV/Excel/Parquet） | 最轻量、覆盖 15 个公开数据集 | ✅ 必做 |
| **P1** | 数据库/数仓（MySQL/PG/Hive/StarRocks） | 企业核心场景的入口 | ⏳ Demo 一个连接器 |
| **P2** | 业务系统 API（HR/CRM/OA/Salesforce） | 长尾系统，定制化连接 | 🔶 UI 占位"已支持" |
| **P3** | 内置亚信数据中台 | 借公司既有产品力 | 🔶 PPT 讲，不做 |

> **现实主义**：比赛 7 天只做 P0；P1 给一个 PostgreSQL demo 连接器；P2/P3 在 UI 里展示"已支持图标"，决赛 PPT 里讲清产品化路径。

## 六、差异化（vs 5 类对手）

| 对手 | 强项 | Table-Talker 的胜负手 |
|---|---|---|
| **Tableau / PowerBI** | 看板表现力强、生态成熟 | **零学习成本**（不用学拖拽语法）；**临时性场景**（不为新需求建看板） |
| **ChatGPT + Code Interpreter** | 通用性强 | **私有部署**、**连企业数据**、**合规** |
| **普通 NL2SQL（如 Vanna）** | 开源便宜 | **不止 SQL**：多轮 / 自动可视化 / 商业语言总结 / 双模式 |
| **企业自建 BI** | 数据贴近 | **不依赖 IT 排期**、**通用化** |
| **AI Agent 类（Dify/Coze）** | 工作流灵活 | **业务/管理领域专精**、**术语库**、**双模式 UX** |

---

## 七、关键约束

| 维度 | 约束 |
|---|---|
| 数据安全 | 私有部署、数据不出企业网；用户上传文件分租户隔离 |
| 可解释性 | 每条结论必须能追溯到 SQL + 原始数据行 |
| 模型 | 部署期必须用主办方指定国产模型（通义千问 3.6 Plus / DeepSeek 3.2）；开发期 Cursor/Claude Code 可用 |
| 成本控制 | 分层路由：小模型做路由/SQL 校验，大模型做最终报告 |
| 性能 | 比赛阶段不严格考时效；产品化阶段单查询 < 10s 体感即可 |
| 用户上手 | 新用户 5 分钟内能问出第一个有效问题 |

## 八、不做的事（防止 scope creep）

- ❌ **实时流处理**（不是产品定位，让位给 Flink 类）
- ❌ **大规模 ETL 工程**（不取代数据工程师）
- ❌ **持久监控大屏**（让位给 BI 老牌产品；我们是"临时性 + 探索性"）
- ❌ **深度建模 / 机器学习预测**（不替代数据科学家）
- ❌ **非结构化数据**（PDF/图片/音频留给赛题一类工具）
- ❌ **复杂权限管理**（V1 先单租户，多租户 V2 再做）

> 这些问题不在意图阶段回答，PRD 阶段必须明确。

- [ ] 失败兜底：模型答不出怎么办？SQL 跑超时怎么办？
- [ ] 计费模型：按查询数？按租户？按团队？

## 十三、关键判断 & 风险

### 已对齐
- ✅ 通用平台定位（不聚焦单一场景）
- ✅ 双模式（管理者 + 运营/分析师）
- ✅ 三态输出（聊天 / 看板 / 报告）
- ✅ 四类数据源（分优先级）

### 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 通用 = 都不深 | Demo 时被评委追问"具体怎么用在 XX 场景" | 准备 3 个不同领域的精彩示例，提前打磨话术 |
| 双模式增加工作量 | 7 天做不完 | 双模式 = 同一后端 + 不同 Prompt + 不同 UI 密度，**不要做成两套系统** |
| 三态输出工作量大 | 看板/报告可能赶不出来 | 看板 V0 = 把多个图表卡片堆叠在一个页面（不要做拖拽编辑）；报告 V0 = 把对话历史导成 PDF（不要做版式设计） |
| 全数据源工作量大 | 库/API/中台连接器各自要花时间 | MVP 只做文件上传；其他在 UI 里"占位"，PPT 里讲 |
| 4 人协作 | 全栈 + 算法 + UI + 部署，分工不清就崩 | 立即明确分工（见下文建议） |

## 十四、立刻可决策的 4 件事

1. **MVP 范围确认**：你看上面 🔴 9.1 这一段，**有没有要减/要加**的？
2. **双模式默认**：默认进入商业语言模式还是让用户选？
3. **报告 V0 是 PDF 还是 Word？**（PDF 渲染好但难编辑；Word 易编辑但格式难控）
4. **4 人分工建议**（如果你认可，立刻发给队长）：
   - **算法**（Agent 主流程 + GraphRAG + TTL + NL2SQL）：1 人，最重
   - **后端**（FastAPI + 数据加载 + SQL 执行 + 沙盒 + 评测脚本）：1 人
   - **前端**（Streamlit/React + 双模式 UI + 看板 + 报告导出）：1 人
   - **部署/数据/视频**（亚信云 + Docker + 15 数据集 schema 整理 + 视频）：1 人（队长候选，因为多线协调）
